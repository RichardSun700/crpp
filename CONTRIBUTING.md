# Contributing to CRPP

Thank you for helping make context rights concrete and testable.

## Where to contribute

- Discussions: early ideas and cross-disciplinary questions.
- Issues: scoped defects, translation differences, security-safe conformance gaps, and documentation improvements.
- CEPs: new protocol objects, normative rights changes, breaking changes, or governance changes.
- Pull requests: reviewed changes from a fork or topic branch.

## Required for normative changes

A normative change must include:

1. English normative text with stable rule IDs;
2. the aligned Chinese translation or a tracked translation issue;
3. updated JSON Schema when applicable;
4. at least one valid and one invalid synthetic fixture;
5. changelog entry;
6. threat-model impact analysis.

## Privacy rule

Never submit real employer, employee, contractor, customer, patient, partner, or user context. Remove local paths, credentials, identifiers, unique incidents, and reconstructable confidential facts. Use synthetic examples.

## Developer Certificate of Origin

Contributors certify the Developer Certificate of Origin 1.1 by adding `Signed-off-by: Name <email>` to commits. This repository does not require contributors to assign copyright to Memova or another single company.

## Review

Pull requests require a non-author reviewer and passing required checks. Reviewers consider protocol semantics, minority rights, third-party constraints, privacy leakage, backwards compatibility, translation parity, and test evidence.
